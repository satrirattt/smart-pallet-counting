## ความสามารถและสถานะปัจจุบัน

โปรเจกต์นี้เป็น **เวอร์ชันทดลอง (prototype/demo)** เหมาะสำหรับสาธิตการอ่าน
CSV การสรุปยอด และการสร้าง SQLite schema ไม่ใช่ระบบนับสินค้าพร้อมใช้งานจริง

- อ่าน CSV และรวมจำนวนตามรหัสสินค้าด้วย Python
- สร้างตาราง SQLite และเพิ่มข้อมูลตัวอย่าง
- ตรวจสอบ CSV และการป้องกันข้อมูลซ้ำด้วยชุดทดสอบ

> **ขอบเขต:** ข้อมูลใน CSV และข้อมูลตัวอย่างใน SQLite เป็นคนละชุด
> ตัวสรุป CSV ยังไม่บันทึกผลลงฐานข้อมูล และโปรเจกต์ยังไม่มีโค้ดเชื่อมต่อกล้อง
> หรือเรียกใช้ YOLO/โมเดลตรวจจับวัตถุ

## ติดตั้งและเริ่มใช้งาน

### ขั้นที่ 1: เปิดโฟลเดอร์โปรเจกต์

เปิด Terminal ในโฟลเดอร์ `smart-pallet-counting` ซึ่งมีไฟล์ `summarize.py`
และ `schema.sql`

ตรวจสอบว่าเรียก Python ได้:

```shell
python --version
```

### ขั้นที่ 2: สรุปยอดจาก CSV

รันด้วยไฟล์ตัวอย่าง:

```shell
python summarize.py
```

หรือระบุไฟล์ CSV อื่น:

```shell
python summarize.py path/to/camera_counts.csv
```

โปรแกรมต้องการคอลัมน์ `product_code` และ `quantity`; รหัสสินค้าต้องไม่ว่าง
และจำนวนต้องเป็นจำนวนเต็มบวก หากข้อมูลไม่ถูกต้อง โปรแกรมจะแจ้งข้อผิดพลาด

### ขั้นที่ 3: สร้างฐานข้อมูล SQLite

```shell
python init_db.py
```

คำสั่งนี้รัน [`schema.sql`](schema.sql) และสร้างไฟล์ `camera_counts.db`
ในโฟลเดอร์โปรเจกต์ ตารางที่ได้ชื่อ `camera_count_results` การรันซ้ำจะไม่เพิ่ม
ข้อมูลตัวอย่างชุดเดิมซ้ำ ไฟล์ฐานข้อมูลถูกละเว้นจาก Git

### ขั้นที่ 4: รันทดสอบ

```shell
python -m unittest -v
```

ชุดทดสอบสร้างฐานข้อมูลชั่วคราวในหน่วยความจำ จึงไม่เปลี่ยน
`camera_counts.db`

## ตัวอย่างผลงาน

ผลลัพธ์จริงของคำสั่ง `python summarize.py` กับ CSV ตัวอย่าง:

```text
BOX-A: 5
BOX-B: 5
BOX-C: 1
```

ยอดคำนวณจากแถวใน [`camera_counts.csv`](camera_counts.csv):

- `BOX-A` = 3 + 2 = 5
- `BOX-B` = 1 + 4 = 5
- `BOX-C` = 1

ยังไม่มีภาพหน้าจอหรือ GIF ในโปรเจกต์ จึงแสดงผลจาก Terminal แทน

## รูปแบบข้อมูล

### CSV

ไฟล์ [`camera_counts.csv`](camera_counts.csv) เป็นตัวอย่างรายการตรวจนับ
แต่ละแถวมีคอลัมน์:

- `camera_id` — รหัสกล้อง (ไม่ใช้สรุปยอด)
- `captured_at` — เวลาที่บันทึก (ไม่ใช้สรุปยอด)
- `product_code` — รหัสสินค้า (ใช้จัดกลุ่ม)
- `quantity` — จำนวนที่ตรวจพบ (ใช้รวมยอด)
- `confidence` — คะแนนความมั่นใจของโมเดล (ไม่ใช้สรุปยอด)

`confidence` เป็นคะแนนความมั่นใจ ไม่ได้รับประกันว่าเป็นเปอร์เซ็นต์ความถูกต้อง

เมื่อรัน [`summarize.py`](summarize.py) โปรแกรมใช้เฉพาะ `product_code` และ
`quantity` เพื่อรวมยอดตามรหัสสินค้า ส่วนคอลัมน์อื่นมีไว้เป็นข้อมูลประกอบ
และยังไม่ถูกบันทึกลง SQLite

### SQLite

ตาราง `camera_count_results` ที่สร้างจาก [`schema.sql`](schema.sql) มีคอลัมน์:

- `id` — หมายเลขรายการที่ SQLite กำหนด
- `timestamp` — วันที่และเวลาที่นับ
- `camera_id` — รหัสกล้อง
- `object_count` — จำนวนวัตถุที่ตรวจพบ; ห้ามติดลบ แต่เป็น 0 ได้
- `qr_text` — ข้อความจาก QR เช่น `PALLET-A`; เป็น `NULL` เมื่อไม่มี

ข้อมูลตัวอย่างเดิมใน schema (เรียงตาม `id`):

- `id 1` — `2026-11-09T09:00:00+07:00`, กล้อง `CAM-01`, นับได้ 3, QR `PALLET-A`
- `id 2` — `2026-11-09T09:01:00+07:00`, กล้อง `CAM-01`, นับได้ 1, ไม่มี QR
- `id 3` — `2026-11-09T09:02:00+07:00`, กล้อง `CAM-02`, นับได้ 2, QR `PALLET-B`
- `id 4` — `2026-11-09T09:03:00+07:00`, กล้อง `CAM-01`, นับได้ 0, ไม่มี QR
- `id 5` — `2026-11-09T09:04:00+07:00`, กล้อง `CAM-02`, นับได้ 4, QR `PALLET-C`

`id` ถูกกำหนดโดย SQLite ตามลำดับการเพิ่มข้อมูลในฐานข้อมูลใหม่ ส่วน `NULL`
หมายถึงไม่ได้อ่าน QR ได้ ข้อมูลชุดนี้ตรงกับค่าใน [`schema.sql`](schema.sql)

### ความสัมพันธ์ระหว่าง CSV กับ SQLite

สองส่วนนี้เป็นตัวอย่างคนละรูปแบบและยังไม่ได้เชื่อมกัน:

- CSV สรุปยอดตาม `product_code` เช่น `BOX-A`
- SQLite เก็บผลนับตาม `camera_id`, `timestamp`, `object_count` และ `qr_text`
- การรันสคริปต์สรุป CSV ไม่ได้เพิ่มข้อมูลลงในฐานข้อมูล

ดังนั้นผล CSV และแถว SQLite ไม่จำเป็นต้องมีรหัสสินค้า จำนวน หรือข้อมูลตรงกัน

## การป้องกันข้อมูลซ้ำ

- Unique index บน `(camera_id, timestamp)` ห้ามคู่กล้องและเวลาเดียวกันซ้ำ
- `ON CONFLICT ... DO NOTHING` ข้ามรายการซ้ำโดยไม่เขียนทับข้อมูลเดิม
- หากตารางเดิมมีคู่กล้อง/เวลาซ้ำอยู่แล้ว ต้องจัดการรายการซ้ำก่อนสร้าง index

## การส่งงานและข้อจำกัด

### ส่งเป็นเวอร์ชันทดลองได้ไหม?

ส่งได้ หากโจทย์ต้องการ **ต้นแบบ/เวอร์ชันทดลอง** ที่สาธิต Python, CSV และ SQLite
แต่ควรระบุในรายงานหรือการนำเสนอให้ชัดว่าเป็นข้อมูลจำลองและยังไม่เชื่อมกล้องจริง
อย่านำเสนอว่าเป็นระบบนับสินค้าอัตโนมัติที่พร้อมใช้งานแล้ว

### ควรส่งไฟล์อะไร?

โดยทั่วไปให้ส่งโฟลเดอร์โปรเจกต์ที่มีไฟล์ซอร์ส, CSV, schema, tests และ README
ตามรายการด้านบน ไม่จำเป็นต้องส่ง `camera_counts.db` เพราะสร้างใหม่ได้ด้วย
`python init_db.py` และไฟล์นี้ถูกละเว้นจาก Git อยู่แล้ว

ก่อนส่ง แนะนำให้ตรวจว่า:

- README อธิบายขอบเขตและข้อจำกัดตรงกับสิ่งที่โปรแกรมทำจริง
- `python summarize.py`, `python init_db.py` และ `python -m unittest -v` รันผ่าน
- ส่งไฟล์ภาพหน้าจอหรือ GIF เพิ่ม หากผู้รับกำหนดให้มีตัวอย่างผลงานแบบภาพ
- เพิ่มส่วนเชื่อมกล้อง/โมเดลและบันทึกผลเข้า SQLite ก่อน หากโจทย์ต้องการระบบใช้งานจริง

หากเป็นงานส่งอาจารย์หรือประกวด ให้ตรวจรูปแบบไฟล์และหัวข้อที่ผู้รับกำหนดอีกครั้ง
เช่น ปก รายงาน แหล่งที่มาของข้อมูล หรือใบอนุญาต ซึ่ง README อย่างเดียวอาจไม่เพียงพอ

> `schema.sql` ใช้ SQLite ไม่ใช่ SQL Server/T-SQL
