# smart-pallet-counting

**ไฟล์ Python และ SQLite schema เวอร์ชันทดลอง**

ต้นแบบสำหรับทดลองสรุปจำนวนสินค้าจากไฟล์ CSV และสร้างฐานข้อมูลตัวอย่างด้วย
SQLite ใช้ข้อมูลจำลองจากกล้องเพื่อลองขั้นตอนการประมวลผลและการจัดเก็บข้อมูล

## ความสามารถและสถานะปัจจุบัน

- อ่าน CSV และรวมจำนวนตามรหัสสินค้าด้วย Python
- สร้างตาราง SQLite และเพิ่มข้อมูลตัวอย่าง
- ตรวจสอบ CSV และการป้องกันข้อมูลซ้ำด้วยชุดทดสอบ

> **ข้อจำกัด:** ตัวสรุป CSV และฐานข้อมูลยังทำงานแยกกัน ผลรวมจาก Python
> ไม่ได้บันทึกลง SQLite โดยอัตโนมัติ และยังไม่มีโค้ดเชื่อมต่อกล้องหรือเรียกใช้ YOLO

## ติดตั้งและเริ่มใช้งาน

### ขั้นที่ 1: เปิดโฟลเดอร์โปรเจกต์

เปิด Terminal ในโฟลเดอร์ `smart-pallet-counting` ซึ่งมีไฟล์ `summarize.py`
และ `schema.sql`

ตรวจสอบว่าเรียก Python ได้:

```shell
python --version
```

### ขั้นที่ 2: สรุปยอดจาก CSV

รันด้วยไฟล์ตัวอย่าง:

```shell
python summarize.py
```

หรือระบุไฟล์ CSV อื่น:

```shell
python summarize.py path/to/camera_counts.csv
```

โปรแกรมต้องการคอลัมน์ `product_code` และ `quantity`; รหัสสินค้าต้องไม่ว่าง
และจำนวนต้องเป็นจำนวนเต็มบวก

### ขั้นที่ 3: สร้างฐานข้อมูล SQLite

```shell
python init_db.py
```

คำสั่งนี้รัน [`schema.sql`](schema.sql) และสร้างไฟล์ `camera_counts.db`
ในโฟลเดอร์โปรเจกต์ ตารางที่ได้ชื่อ `camera_count_results` การรันซ้ำจะไม่เพิ่ม
ข้อมูลตัวอย่างชุดเดิมซ้ำ ไฟล์ฐานข้อมูลถูกละเว้นจาก Git

### ขั้นที่ 4: รันทดสอบ

```shell
python -m unittest -v
```

ชุดทดสอบสร้างฐานข้อมูลชั่วคราวในหน่วยความจำ จึงไม่เปลี่ยน
`camera_counts.db`

## ตัวอย่างผลงาน

ผลลัพธ์จริงของคำสั่ง `python summarize.py` กับ CSV ตัวอย่าง:

```text
BOX-A: 5
BOX-B: 5
BOX-C: 1
```

ยอดคำนวณจากแถวใน [`camera_counts.csv`](camera_counts.csv):

- `BOX-A` = 3 + 2 = 5
- `BOX-B` = 1 + 4 = 5
- `BOX-C` = 1

ยังไม่มีภาพหน้าจอหรือ GIF ในโปรเจกต์ จึงแสดงผลจาก Terminal แทน

## รูปแบบข้อมูล

### CSV

ไฟล์ [`camera_counts.csv`](camera_counts.csv) มีคอลัมน์:

- `camera_id` — รหัสกล้อง (ไม่ใช้สรุปยอด)
- `captured_at` — เวลาที่บันทึก (ไม่ใช้สรุปยอด)
- `product_code` — รหัสสินค้า (ใช้จัดกลุ่ม)
- `quantity` — จำนวนที่ตรวจพบ (ใช้รวมยอด)
- `confidence` — คะแนนความมั่นใจของโมเดล (ไม่ใช้สรุปยอด)

`confidence` เป็นคะแนนความมั่นใจ ไม่ได้รับประกันว่าเป็นเปอร์เซ็นต์ความถูกต้อง

### SQLite

ตาราง `camera_count_results` ที่สร้างจาก [`schema.sql`](schema.sql) มีคอลัมน์:

- `id` — หมายเลขรายการที่ SQLite กำหนด
- `timestamp` — วันที่และเวลาที่นับ
- `camera_id` — รหัสกล้อง
- `object_count` — จำนวนวัตถุที่ตรวจพบ; ห้ามติดลบ แต่เป็น 0 ได้
- `qr_text` — ข้อความจาก QR เช่น `PALLET-A`; เป็น `NULL` เมื่อไม่มี

ข้อมูลตัวอย่างเดิมใน schema (เรียงตาม `id`):

- `id 1` — `2026-11-09T09:00:00+07:00`, กล้อง `CAM-01`, นับได้ 3, QR `PALLET-A`
- `id 2` — `2026-11-09T09:01:00+07:00`, กล้อง `CAM-01`, นับได้ 1, ไม่มี QR
- `id 3` — `2026-11-09T09:02:00+07:00`, กล้อง `CAM-02`, นับได้ 2, QR `PALLET-B`
- `id 4` — `2026-11-09T09:03:00+07:00`, กล้อง `CAM-01`, นับได้ 0, ไม่มี QR
- `id 5` — `2026-11-09T09:04:00+07:00`, กล้อง `CAM-02`, นับได้ 4, QR `PALLET-C`

`id` ถูกกำหนดโดย SQLite ตามลำดับการเพิ่มข้อมูลในฐานข้อมูลใหม่ ส่วน `NULL`
หมายถึงไม่ได้อ่าน QR ได้ ข้อมูลชุดนี้ตรงกับค่าใน [`schema.sql`](schema.sql)

---

## การป้องกันข้อมูลซ้ำ

- Unique index บน `(camera_id, timestamp)` ห้ามคู่กล้องและเวลาเดียวกันซ้ำ
- `ON CONFLICT ... DO NOTHING` ข้ามรายการซ้ำโดยไม่เขียนทับข้อมูลเดิม
- หากตารางเดิมมีคู่กล้อง/เวลาซ้ำอยู่แล้ว ต้องจัดการรายการซ้ำก่อนสร้าง index
